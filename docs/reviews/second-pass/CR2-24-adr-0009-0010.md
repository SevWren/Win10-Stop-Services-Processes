## ADR 0010 — Main Loop Sleep Timing

### Verification checklist

| Check | Result |
|---|---|
| Passive main loop with `Sleep(50)` at lines 147-149 | PASS |
| Active monitoring loop with `Sleep($MAIN_LOOP_SLEEP_MS)` (500 ms) | PASS |
| Two loops exist independently (two-loop architecture confirmed) | PASS |
| `$MAIN_LOOP_SLEEP_MS` defined in a config region | PASS |

### Evidence

**Passive main loop** — `Stop Services Processes.au3` lines 147-149:
```autoit
While 1   ; Main loop — passive. Hotkeys drive all behavior.
    Sleep(50)
WEnd
```
Exists at the top level of the script, outside all functions. This is the loop the CLAUDE.md baseline describes.

**Active monitoring loop** — `ToggleScript()` function, line 166-177:
```autoit
While $bScriptRunning   ; active monitoring loop — exits when Shift+F1 sets $bScriptRunning = False
    If _CheckElapsedTime($iLastStopProcesses, $PROC_POLL_INTERVAL_SEC) Then ...
    If _CheckElapsedTime($iLastStopServices, $SVC_POLL_INTERVAL_SEC) Then ...
    Sleep($MAIN_LOOP_SLEEP_MS)
    _MiscPopups()
WEnd
```
`Sleep($MAIN_LOOP_SLEEP_MS)` is at line 175.

**Two-loop independence** — the passive loop (`While 1`) runs always at the top level; the active loop (`While $bScriptRunning`) runs only when `ToggleScript()` is executing (i.e., after Shift+F1 activates it). They are structurally independent: the passive loop is not inside `ToggleScript()`, and `ToggleScript()` is a hotkey-fired function that returns to the passive loop when `$bScriptRunning` becomes `False`. The two loops do not nest.

**`$MAIN_LOOP_SLEEP_MS` definition** — line 44, inside the `#Region ;Timing constants` / `#EndRegion` config region (lines 39-48):
```autoit
Global Const $MAIN_LOOP_SLEEP_MS       = 500     ; active monitoring While loop sleep (ms)
```
This is the designated single-definition point for all timing constants, consistent with the region comment "Single definition point for all interval values."

### Format compliance (ADR-FORMAT.md)

ADR 0010 provides:
- H1 title: present
- Status frontmatter: **ABSENT** — ADR 0009 carries `**Status**: accepted`; ADR 0010 does not. The format spec marks Status as optional ("When absent, treat the ADR as accepted"), so this is a minor omission, not a violation. No action required unless project policy requires explicit status on all ADRs.
- Context/decision paragraph: **ABSENT** — the ADR opens directly with `## Considered Options` after the H1 title. The format requires "1-3 sentences: what's the context, what did we decide, and why" before optional sections. The title line itself carries the decision implicitly ("50 ms passive loop, 500 ms active monitoring loop") and the Considered Options section identifies the chosen option, but no standalone context paragraph exists. This is a minor structural gap.
- Considered Options (H2): present
- Consequences (H2): present

**Finding F-01 (minor)**: ADR 0010 is missing the mandatory introductory context/decision paragraph. The title encodes the decision outcome, and the chosen option is identified in Considered Options, so no information is lost — but the format requires at least one sentence of prose before the first optional section. Recommend adding a 1-2 sentence opening paragraph. No accuracy issue; purely structural.

**Finding F-02 (minor)**: ADR 0010 has no `**Status**: accepted` line. Per the format spec this is optional and defaults to accepted when absent. No action required; noted for consistency with ADR 0009.

### Content accuracy

The ADR's claim that "CR-09 finding P-05 conflated" the two loops cannot be verified from the source files alone (CR-09 is not in scope), but the underlying factual claim — that two distinct loops exist with different sleep values — is verified correct against the source. The ADR's characterization of the two loops is accurate in every verifiable detail.

### Verdict: PASS with minor format notes (F-01, F-02)
